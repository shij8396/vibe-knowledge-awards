# 开场闪黑与吸收光束修复 — 2026-10-10

本记录来自开源前的本地开发与验收；恢复点仅存在于原开发仓库。保留原粒子数量、单渲染器、MSAA、HDR/ACES和Bloom配置。

## 原因与最终修改

1. **Shader无效值**：intro.ts的边缘光包含 `pow(1-abs(dot(N,V)),2.6)` 与2.7次幂；energyStructure.ts包含1.4次幂。归一化向量的点积仍可能因浮点误差略大于1，使幂底数为负，产生NaN。这类像素经Bloom多级滤波可污染大面积输出。现在对相关边缘光幂底数取非负下界，原子和核心同类计算也加保护。
2. **自动降画质顺序**：main.ts原本在render.render()之后调用lowerQuality()->resize()，清空刚完成的帧。现在在绘制前完成质量调整，使新尺寸立即得到完整画面。
3. **光束偏离**：EnergyMechanism与AtomicScene共用了发射端的y=-0.72、z=0.25坐标，入射光实际从原子下方擦过。吸收光迹、外围粒子和光子标记现在共享原子局部中心(0,0,0)；发射端仍保留原来的能级示意坐标。
4. **细节闪烁**：organizedEnergy.ts及recoveredEnergy.ts给微小粒子设置柔和最小像素覆盖，并以面积比例补偿亮度；energyStructure.ts为远处亚像素细丝设置覆盖补偿。粒子数、流场和能量丝几何保持。

先前对录制缓冲区与MSAA的猜测经实际检查未解决黑帧；最终没有保留preserveDrawingBuffer、关闭MSAA或gl.finish的实验改动。真正有效的改动是Shader数值保护与降画质时序修复。之前的静态截图验收漏掉了这种偶发黑帧，本次采用连续帧读回检查。

## 已执行

- 最终构建成功、22项测试通过。Vite仍有Three.js分块大小提示。
- 修复前自然播放读回：1–12秒范围出现多次全黑帧；仅保留缓冲区、同步GPU或关闭MSAA均不能消除。
- Shader与时序修复后：同样12秒自然播放读回两次，分别351与349个1–12秒有效帧，黑帧0。两次均触发1440→1224像素宽度的自动降画质。正常MSAA设置保留，第二次已移除缓冲区实验设置。
- 实际查看3、6、8、12、31.5、33.5、42、168秒；31.5及33.5秒的光束现在正中原子。发射方向未改。
- 修改前后截图保留在原开发环境；未随本开源副本上传。
- 完整0–170秒重新录制已保存为film-fixed.webm（59,511,223字节），8466个渲染帧。编码文件1–12秒中心画面另解码逐帧检查，结果见下方。原始指标为metrics.json。旧录像保存在film-before-flicker-fix.webm，未删除。
